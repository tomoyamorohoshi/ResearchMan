# Case Study リサーチ v3 仕様（2026-10-20 オーナーインタビュー反映）

対象: `scripts/auto-research-cc.mjs`（Case Study 日次収集）と週次チューンアップ（`scripts/biweekly-tuneup.mjs`）。
前提: docs/RADAR_V2_DESIGN.md（関門 A/B/C・情報源レジストリ・ベイクオフ）を土台にし、v3 で範囲・量・学習ループを拡張する。

## 0. 目的（オーナーの意図）

- 「AI×クリエイティブ」だけでなく、**テクノロジー×クリエイティブ全般**を拾う。例: 伝統工芸×デジタルファブリケーション、新しいデータビジュアライゼーション、新しいメディアを発明した広告、アルゴリズミックな建築。
- 広告・施策・デザインは **Cannes Lions / D&AD / NY ADC / One Show / Clio / Ars Electronica / デザイン・データ系の賞（Information is Beautiful Awards・Type Directors Club・iF/Red Dot 等）を受賞しているような**仕事が意図に合う。ただしそれだけでは不十分で、**アート、アワード向きでない新しい表現手法・アプローチも取りこぼさない**。
- **常に全世界**。地域でラウンドを分けない。
- 基準にあと一歩の「惜しい候補」も拾い、オーナーの fav/トラッシュで精度を上げる。

## 1. 決定事項（インタビュー結果）

| 項目 | 決定 |
|---|---|
| ラウンド設計 | 領域レンズ4本 × 全世界、毎日4本とも回す |
| 鮮度 | 作品の公開・発表が**直近14日**（受賞発表は鮮度の例外にしない） |
| 採用基準 | A/B/C に **D（他の仕事に転用できる新しい手法・アプローチ。実験・試作も可）** を追加 |
| 受賞の扱い | 採用基準にはしない。**「何を探すかの物差し」（受賞作の具体例）と「探す場所」（各賞の受賞・SL発表）**で反映 |
| 件数 | 基準を満たすもの: 目安 5〜10件/日、無ければ 0〜5 でよい（基準は緩めない） |
| 不足時 | 届かなかったレンズを別の検索語・別言語で最大2ラウンド追加 |
| 惜しい候補 | 別枠で **1日3件まで**採用。サイト上は**区別せず混ぜる**（内部フラグのみ） |
| 言語 | 英語・日本語に加え、中国語・韓国語・スペイン語/ポルトガル語・フランス語・ドイツ語でも検索。記事は日本語 |
| 巡回先 | 候補リスト（ベイクオフで選別）＋ AI の自由探索のハイブリッド。時間がかかってよい |
| 学習 | 週次見直しで **判定の具体例（採用例・不採用例 各最大8件）と探索テーマ・巡回先の優先度は自動更新**。**採用基準 A〜D の文面は変更案を LINE で提示し、LINE で承認／フィードバック** |

## 2. 領域レンズ（`data/research-tuning.json` の `cc.roundFoci` を置き換え）

全レンズ共通: 全世界・多言語。4類型（読み替え一手／生成的ブランドID／素材が主張する／AIが手段）は残し、v3 で「(e) 手法の発明」「(f) 新しいメディアの発明」を追加。

1. **広告・施策・ブランド体験** — 受賞級の広告・PR・アクティベーション・メディア発明。物差し: Cannes Grand Prix／D&AD Pencil／ADC Cube／One Show Pencil／Clio Grand の近年作。
2. **デザイン・ブランド・情報表現** — ブランドID、タイポグラフィ、データビジュアライゼーション、インタラクティブ・Web、編集デザイン。物差し: D&AD Graphic/Digital Design、IIB Awards、TDC、ADC Design。
3. **アート・建築・クラフト×テクノロジー** — メディアアート、インスタレーション、アルゴリズミック／コンピュテーショナル建築、伝統工芸×デジタルファブリケーション、素材研究。物差し: Ars Electronica Prix／STARTS Prize、Dezeen Awards、建築・デザインビエンナーレ。
4. **新しい表現手法・テクノロジー表現** — アワード向きでない実験・手法の発明（生成・センシング・ロボティクス・音・映像・ライブ演出・XR）。プロトタイプ・個人作品も可。※ツールや研究そのものは Technology タブ、作品・表現は Case Study。

## 3. 採用基準（関門）の改訂

- 基準文と具体例を**コードから data ファイル `data/case-gate.json` に移す**（LINE 承認・週次自動更新でコードを書き換えないため）。`scripts/lib/case-gate-criteria.mjs` はこのファイルを読む。
- 追加: **D: 手法・アプローチの新規性** — 完成度や受賞見込みを問わず、他の仕事に転用できる新しい手法・アプローチがある（個人の実験・試作も可）。
- 判定は3段階に: `accept`（A〜D のいずれかを満たす）／`borderline`（どれかに「あと一歩」。理由必須）／`reject`。
- **具体例（リトマス）**: 採用例・不採用例 各最大8件。初期値は「対象アワードの近年の受賞作（なぜ良いかの一文付き）」＋オーナーの既存お気に入り上位から作る。週次で自動入れ替え（§5）。
- `gateTier: "accept" | "borderline"` を cases.json のエントリに記録（表示には使わない）。

## 4. 収集フロー（auto-research-cc.mjs）

1. 4レンズを順に発見（各ラウンドで多言語クエリ。レンズごとに優先巡回先＋AI 自由探索）。
2. 関門1（発見時の自己判定）で accept / borderline / reject。
3. 重複除去・リンク死活・サムネイル検証（現行どおり）。展覧会告知（国内）は Exhibition へ引き継ぎ（現行どおり）。
4. 記事化 → 関門2（最終判定）。
5. 採用上限: accept は1回最大10件、borderline は別枠で最大3件（accept が多い日でも borderline 枠は維持。borderline は gate スコア上位から）。
6. accept が5件未満なら、件数の少ないレンズを別言語・別検索語で最大2ラウンド追加。基準は緩めない。
7. 実行時間の上限: 発見フェーズ全体 40分 → **90分**（時間はかかってよいとの指示。gitロック待ち・他ジョブとの時刻衝突を確認して設定）。

## 5. 週次見直し（biweekly-tuneup.mjs）の拡張

入力に追加: Case Study の fav/トラッシュのうち **borderline のもの**（＝選別の結果）と、gateTier 別の fav/トラッシュ率、却下ログ（`logs/rejections-*.jsonl`）、レンズ別の採用数。

| 変更対象 | 方法 | 上限・安全策 |
|---|---|---|
| 判定の具体例（採用例/不採用例） | **自動**。borderline で fav されたもの→採用例候補、トラッシュ→不採用例候補 | 各最大8件、1回の入れ替え最大3件、dry-run 検証・失敗時は全戻し（現行の仕組み） |
| 探索テーマ文言・巡回先の優先度（tier/enabled） | **自動** | 既存ガードレール（文言のみ・各5件まで）を使い、`checkSourcesChange` を実際に配線する |
| 採用基準 A〜D の文面 | **LINE で提案 → LINE で承認／フィードバック** | 下記 §6 |

## 6. 基準文の変更案を LINE で承認／フィードバック

- 週次見直しが基準文の変更案を作ったら、LINE に送る（system 通知を LINE に出さない方針の**例外**。オーナーの判断が要るため）。
  - 形式: 「基準の変更案 #<ID>」／変更前・変更後（差分）／理由（根拠となった fav・トラッシュ例）／操作方法。
- 返信の書式（Studio の LINE webhook に追加。`studio/server/line/classify.ts`）:
  - `承認 <ID>` → `data/case-gate.json` に反映 → 監査・commit・push → 「反映しました」と返信。
  - `却下 <ID>` → 破棄して記録。
  - `修正 <ID> <自由文>` → フィードバックを踏まえた修正案をその場で作り直して再送（Studio ジョブ）。
  - 7日間返信がなければ失効（次の週次見直しで再検討）。
- 承認待ちの案は `data/inbox/gate-proposals.json` に保存（ID・状態・作成日・差分・フィードバック履歴）。

## 7. 巡回先の拡張

- 新レンズ向けの候補を `data/sources.json` に `enabled:false` で追加し、`scripts/bakeoff-sources.mjs` で採点 → 採用率の高いものを有効化。候補の例（ベイクオフで確定）:
  - 受賞・SL 発表: canneslions.com、dandad.org、oneclub.org（ADC/One Show）、clios.com、ars.electronica.art、informationisbeautifulawards.com、tdc.org
  - データ表現: flowingdata.com、nightingaledvs.com、pudding.cool、datavisualizationsociety
  - 建築・計算設計: archdaily.com、dezeen.com（既存）、designboom.com（既存）、parametric-architecture.com
  - クラフト×デジファブ・素材: materialdistrict、core77、fabbaloo、colossal（既存）
  - 多言語: 中国語（数英網 digitaling.com 等）、韓国語、スペイン語/ポルトガル語、仏独の広告・デザインメディア
- 優先巡回先に無い分野は AI に「その分野の一次情報・専門メディアを自分で選んで検索」させる（ハイブリッド）。

## 8. 範囲外

- Exhibition タブ（国内の開催前/中の展示）の仕様は変えない。海外の展示・アート作品は Case Study で「作品」として扱う。
- Technology タブ（ツール・研究）の基準は変えない。
- サイトの表示（borderline の印は付けない）。

## 9. 検証

- ユニット: case-gate の3段階正規化、data/case-gate.json 読み込み、borderline 枠の上限、レンズ×多言語プロンプト生成、LINE の 承認/却下/修正 の解釈。
- dry-run: `npm run auto-research:cc:dry` で4レンズ＋追加ラウンドが回り、accept/borderline/reject が記録されること。実行時間の実測。
- 回帰の物差し: §0 の例（伝統工芸×デジファブ、データビジュアライゼーション、メディア発明の広告、アルゴリズミック建築）に当たる直近の実例を手動で数件集め、dry-run の発見でそれらの分野が候補に出るかを確認。
- 運用後: research-health（watchdog）で追加ペース・レンズ別採用数・borderline の fav/トラッシュ率を監視。

### 10-A. Phase 2 実装で決めた内容（2026-10-20）

- 言語: 各レンズに英語・日本語を常に、加えて回転枠2言語。回転枠は中国語/韓国語/スペイン語・ポルトガル語/フランス語/ドイツ語の5言語を、4レンズ×2スロット=8スロットで巡回（日ごとに3つずれる）。同一レンズ内の2言語は重複せず、毎日5言語すべてがどこかで使われる（`scripts/lib/case-lenses.mjs` の `lensLanguagePlan`）。
- レンズ順: 4レンズを毎日1回ずつ。開始位置のみ日替わり（`lensOrderForDay`）＝accept 上限10件に先に達しても同じレンズが毎日有利にならないようにする。
- WebSearch 上限: 1ラウンド10回→16回（4言語×3回＋情報源巡回・URL確認4回）。発見タイムアウト 10分→15分。
- 発見フェーズの上限 90分は「発見呼び出しの累積時間」で測る（記事化は含めない）。新規ラウンド（埋め合わせ・追加）はこの上限に達していたら始めない。
- gateScore は 1〜10 の整数（発見・記事化の両方で出力）。範囲外・欠損は最低点1（borderline 枠に紛れ込ませない）。
- borderline の記事化は全ラウンド後に発見時の gateScore 上位から。最終 tier は関門2の判定。採用枠の適用は記事化後（accept 先着10件、borderline は関門2の gateScore 降順3件）。
- cases.json の追加フィールド: `gateTier`（accept|borderline）、`discoveryLens`（1〜4）。表示には使わない。
