# X（Twitter）投稿ルール調査レポート — 事例紹介・クリエイティブテック紹介アカウント向け

- 調査日: 2026-09-27
- 対象アカウント想定: @tomoyamorohoshi（個人・日本語・クリエイティブ/広告従事者向け）
- 目的: 海外広告事例・ブランド体験・音楽レーベルのYouTube企画・インタラクティブサイト・新クリエイティブテックツールを紹介する投稿で、リーチ/エンゲージメントを最大化するための運用ルールとテンプレートを定める
- 表記: **FACT**=一次情報または複数の独立ソースで裏付けが取れた事実 / **INFERENCE**=業界のブログ・二次情報の傾向からの推測、または本レポートでの合成判断
- 注意事項: 2026年のX/Twitterアルゴリズム系情報の多くはSEO目的の後発ブログ記事（postiz, opentweet, socialspool, publora等）が情報源で、相互に転載し合っている可能性が高い。本レポートでは可能な限り一次情報（GitHub上の公式リポジトリ、Elon Musk本人の投稿、大手メディアの一次報道）で裏取りしたものをFACTとし、それ以外は出典を明記した上でINFERENCE扱いとした。具体的な倍率・日付が疑わしいもの（例:「返信はいいねの27倍」等）は数字自体を採用せず、方向性のみ採用している。

## A. Xの仕様とアルゴリズム（2026年9月時点）

### A1. 文字数ルール（FACT）
- 通常投稿の上限は280文字。X Premium加入者は「Long Post」で最大25,000文字、スレッドは最大50投稿まで作成可能。
  出典: [Twitter/X Character Limit 2026: Every Limit Explained](https://fmax.io/blog/twitter-character-limit-2026), [X (Twitter) Character Counter](https://postiz.com/tools/x-character-counter)（2026年時点の複数ツールで一致）
- **重み付けカウント**: URLは常に23文字換算（実際の長さに関係なく固定）。CJK（日本語・中国語・韓国語）文字と一部の絵文字は1文字=2カウント。したがって日本語のみで書くと実質約140文字が上限の目安になる。メディア（画像・動画）の添付自体は文字数を消費しない。
  出典: [Why your 280-character tweet is actually too long: weighted counting explained](https://redmooncalculators.com/blog/twitter-character-counting-explained/), [textlimits.com](https://textlimits.com/blog/x-twitter-character-limit/)
- **実務上の含意**: 日本語運用では「280文字だから長く書ける」は誤りで、実質140字弱が本文の目安。長文で背景解説を入れたい場合はPremium Long Post化かスレッド化が必要。

### A2. メディア仕様（FACT、複数ツール系サイトで一致）
- **画像**: タイムライン上で最も大きく綺麗に表示されるのは16:9（1600×900px、または1200×675px）。4:5縦長（1080×1350px）、1:1正方形（1080×1080px）も対応。アップロード上限は写真5MB、GIF最大15MB（Web）。
  出典: [Sked Social 2026](https://skedsocial.com/blog/twitter-post-size-guide), [HeyOrca 2026](https://www.heyorca.com/blog/x-twitter-media-specs-best-practices-2026)
- **動画**: 推奨解像度1280×720〜1920×1080（16:9）、縦動画9:16も可。無料アカウントは最大512MB・2分20秒。Premiumは最大2時間（1080p）、Premium+は最大4時間・16GBまで拡張。コーデックはH.264(MP4/MOV)+AAC音声が必須。
  出典: [SocialKit](https://socialk.it/en/sizes/x-video-size), [PostFast](https://postfa.st/sizes/x/video)
- **実務上の含意**: 事例紹介はほぼ必ず16:9の動画クリップ（15〜45秒程度に編集）を主素材にするのが最も安全。縦型ショート動画（施策のBTS動画等）も9:16でそのまま使える。

### A3. 外部リンクの扱い（FACT — 一次発言で裏付けあり）
- 2023年10月、Elon Musk自身が「リンク付き投稿はアルゴリズム上不利になる」ことを実質的に認めた。同時期、X上でのリンクカード（画像+見出し付きリンク）表示も縮小された。
  出典: [Slate 2023](https://slate.com/technology/2023/10/elon-musk-x-twitter-news-links-headlines-why.html)
- 2023年8月、Washington Postの分析で、Facebook/Bluesky/Substackや大手ニュースサイトへのリンクに人為的な表示遅延がかけられていたことが報じられた。
- 2024年11月、Musk本人が「本文にリンクを入れる“lazy linking”を抑制するためにリンクは不利にしている。リンクはリプライに置け」と明言。
  出典: [BusinessToday 2024](https://www.businesstoday.in/technology/news/story/elon-musk-confirms-that-x-deprioritises-posts-with-links-to-discourage-lazy-linking-455115-2024-11-26), [Techmeme](https://www.techmeme.com/241125/p22)
- 2026年時点でもこの方針は継続・強化されていると複数の運用系ブログが報告（本文リンクは非リンク投稿比で初期到達が数十%減という具体的数値は二次情報のため未検証=INFERENCE）。回避策としての「リンクはリプ欄に置く」運用は2026年も定石とされている。
  出典（INFERENCE寄り）: [SocialPilot Aug 2026](https://www.socialpilot.co/blog/twitter-algorithm), [teract.ai](https://www.teract.ai/resources/twitter-algorithm-2026)

### A4. 推薦アルゴリズムの重み（FACT — 一次情報のGitHubリポジトリで確認）
- 2023年3月、Twitter（現X）は推薦アルゴリズムを`twitter/the-algorithm`としてOSS公開（当時のHeavy Rankerの概念:いいね・RT・返信・プロフィールクリック等を重み付けしてスコアリング）。
- 2026年1月、xAIが全面刷新した新アルゴリズムを`github.com/xai-org/x-algorithm`として公開、以後4週間おきに更新されている（2026年9月時点で直近更新は9/18・8/14）。
  出典: [github.com/xai-org/x-algorithm](https://github.com/xai-org/x-algorithm)（本レポート作成のため直接WebFetchで確認）
- 同リポジトリの`home-mixer/params/param.rs`から確認できた実際の重み定数（2026年9月時点の値。WebFetch経由の要約のため数値は参考値として扱う）:

| 行動 | 重み定数 | 値 |
|---|---|---|
| いいね | FavoriteWeight | 0.5 |
| 返信 | ReplyWeight | 5.0 |
| リポスト | RetweetWeight | 1.0 |
| 引用 | QuoteWeight | 5.0 |
| リンククリック（本文内リンクを開く） | OpenLinkWeight | 0.2 |
| 一般クリック | ClickWeight | 0.4 |
| 画像展開 | PhotoExpandWeight | 0.05 |
| 動画再生開始 | VideoOpenWeight | 0.07 |
| 滞在（dwell） | DwellWeight | 0.05 |
| 未滞在（離脱） | NotDwelledWeight | -0.02 |
| DMで共有 | ShareViaDmWeight | 5.0 |
| リンクコピーで共有 | **ShareViaCopyLinkWeight** | **20.0（最大の正の重み）** |
| フォロー | FollowAuthorWeight | 4.0 |
| 相互フォロー間の返信ブースト | BidirectionalFollowReplyWeightBoost | 15.0 |
| 「興味なし」 | NotInterestedWeight | -43.2 |
| ブロック | BlockAuthorWeight | -31.2 |
| ミュート | MuteAuthorWeight | -58.8 |
| 通報 | ReportWeight | -234.0（最大の負の重み） |

  **含意（FACT値からの直接読み取り）**: 「いいね」の価値は最も低い部類（0.5）。返信(5.0)・引用(5.0)・DM共有(5.0)・リンクコピー共有(20.0)が圧倒的に価値が高い。一方で本文内リンクを開く行為(OpenLinkWeight 0.2)はいいねより低い評価で、リンクを踏ませること自体はアルゴリズム的に大きな得点源ではない＝「クリックさせる」より「保存・共有・会話させる」設計の方が理にかなう。通報(-234)・ミュート(-58.8)・興味なし(-43.2)は強烈な負の重みなので、釣りタイトルで反感を買う設計は危険。

### A5. Grok化・Premiumブースト（FACT+一部INFERENCE）
- FACT: 2025年から段階的にGrok（軽量版）ベースのランキングに置き換えが進み、2025年後半には全面的にAI駆動（transformerモデルが投稿本文・動画内容を意味的に理解）に移行。
  出典: [Elon Musk 本人ポスト](https://x.com/elonmusk/status/1918592668307010019), [Towards AI 2026](https://pub.towardsai.net/x-open-sourced-its-feed-algorithm-powered-by-grok-e5a13d67e741)
- FACT（2023年公開コードから既知）: Premium（旧Blue）認証アカウントには、フォロー内投稿で4倍、フォロー外投稿で2倍の可視性ブーストが組み込まれていた。2026年時点でも階層別ブースト（Premium / Premium+）が継続していると複数ソースが報告。
- INFERENCE: 「無料アカウントはエンゲージメント中央値ほぼゼロ」等の刺激的な数値は単一の二次情報源のみで検証不可のため採用しない。ただし「非Premiumは相対的に不利」という方向性自体は一次情報の4x/2xブーストと整合するため妥当な前提として扱う。

### A6. ハッシュタグ・投稿時間・dwell time（INFERENCE寄り、複数ソースの傾向一致）
- ハッシュタグの拡散効果は2020年代前半に比べ大きく低下し、2026年時点では「戦略的ハッシュタグ使用による拡散メリットはほぼ消失した」という論調が複数の運用ブログで一致。乱用はむしろスパム的に見え逆効果になりうる（INFERENCE）。
- 日本語ユーザーのアクティブ帯は平日通勤（7-9時）・帰宅後（20-22時）、週末午後（14-17時）という伝統的な経験則が2026年も引き続き言及されている。
- 投稿後15〜30分以内の初速エンゲージメントが「おすすめ」タブでの露出期間の長さを左右するとされる（A4の重み構造とも整合: 初速で返信・共有が付くとブーストが乗る設計と考えられる）。
  出典: [ContentAI 2026](https://contentai.jp/blog/twitter-x-algorithm-2026), [camtsuku.com 2026](https://camtsuku.com/guide/3811)

## B. バズる「事例紹介」ポストの経験則パターン（INFERENCE — 業界ブログ・実務知見の合成）

注記: 個別の投稿URLを検索で一次確認することはできなかったため、具体的な投稿を名指しでは列挙せず、日本語「海外広告事例」系アカウント・英語圏のcurated ad/designアカウントに共通して観測されている**構造パターン**として記述する（すべてINFERENCE、複数の日英ブログの記述が収束する部分を採用）。

1. **1行目が全て**: 最初の1文（〜280字重み内、実質日本語70〜100字程度）で「何がすごいか」を言い切る。スクロールを止める1行目がスレッド/投稿全体のエンゲージメントの8〜9割を左右するという指摘が複数ソースで一致。
2. **結論ファースト＋固有名詞早出し**: 「〇〇（ブランド名）がやったこの施策、〜」のように、ブランド名・国名・驚きの数字を冒頭に置く。「何がすごいか」を一言で要約するラベリング（例:「発想の勝利」「これは反則」等の断定コピー）が使われやすい。
3. **メディアファースト、動画>画像**: 事例紹介では動画クリップ（15〜45秒に編集した見せ場）が画像単体より明確にエンゲージメントが高いという指摘が一致。静止画のみの場合は「Before/After」「ビジュアルのインパクト1枚」に絞る。
4. **数字を入れる**: 「〇〇万回再生」「制作期間◯日」「予算◯円」など検証可能な数字が信頼性と拡散性を高める。
5. **感情・驚き・意外性のフレーミング**: 「まさかの発想」「こんな方法があったのか」等、驚き→回収の構造。ただし煽りすぎる釣りタイトルは通報・興味なし等の負の重み（A4参照）を誘発するリスクがあるため、誇張と正確さのバランスが必要。
6. **改行を使った可読性**: 長い説明文を詰め込まず、1〜2文ごとに改行して縦に流す。モバイル画面での可読性を優先。
7. **絵文字は最小限、記号的に**: 強調点やリスト化のために1〜2個使う程度。装飾過多はノイズになりやすい（絵文字は文字数重みも2倍近くになる点にも注意、A1参照）。
8. **スレッド/引用形式での補足**: 本編は短く強いフックのみ、詳細解説・製作背景・出典リンクはスレッドの2投稿目以降やリプライに送る。これはA3のリンクデプライオリティ回避策とも一致する合理的な構造。
9. **「これ考えた人天才」的な人称化フレーミング**: 施策そのものより「発想した人・チーム」に焦点を当てることで共感と称賛のリプライ（重み5.0）を誘発しやすい。
10. **問いかけ・意見表明での締め**: 最後に「これは良い施策だと思う」「日本でもできそう」等、読者が同意/反論しやすい一言を置き、返信を誘発する（返信の重みはいいねの10倍、A4参照）。
11. **リンクは本文に置かない**: 出典URL・特設サイトURLは本文ではなくリプ欄の1件目に置く（A3の一次情報と整合）。

## C. 生成仕様（LLMプロンプトに組み込む具体スペック）

### C1. テンプレート（3バリエーション）

**テンプレA: フック→正体開示→称賛/驚き締め（単発ポスト、事例紹介の基本形）**
```
[1行目] 固有名詞＋驚きの要約（〜40字目安）
（改行）
[2-3行] 何をしたか（施策の中身を平易に。数字があれば入れる）
（改行）
[締め] 一言の感想・評価（問いかけ or 断定）
```
例の骨格:「〇〇（ブランド）が街中の看板を全部〇〇に変えた。／きっかけは〇〇。反響は◯◯万再生。／これは反則級のアイデア。」
→ 動画/画像を添付。出典URLは本文に入れず、投稿後すぐにセルフリプライで追加。

**テンプレB: スレッド形式（背景・製作過程まで見せたい事例向け）**
```
1投稿目: フック＋結論（テンプレAの1-2行相当）＋メディア
2投稿目: なぜこれがすごいのか（技術・企画の工夫を1-2点）
3投稿目: 出典/参照リンク＋一言まとめ
```
→ 各投稿は短く。1投稿目だけでも単独で成立する強度にする（1投稿目のみRTされる前提）。

**テンプレC: 技術ツール紹介（新クリエイティブテック向け）**
```
[1行目] ツール名＋一言でできること（「これで〇〇が数分で作れる」等）
（改行）
[2行] 使い所・向いている制作物（1つに絞る）
（改行）
[締め] 無料/有料・入手性の一言
```
→ デモ動画（スクリーン録画15-30秒）を最優先。なければbefore/after画像2枚。リンクはリプ欄。

### C2. フックパターン一覧（1行目に使う型）
- 数字インパクト型: 「〇〇万人が見た」「制作費◯円で」「◯日で作られた」
- 意外性型: 「まさか〇〇でこれをやるとは」「〇〇なのに〇〇」
- 人称化型: 「これを考えた人、天才すぎる」「〇〇チームの発想がえぐい」
- 逆説/対比型: 「広告なのに広告っぽくない」「〇〇のはずが〇〇だった」
- 断定ラベル型: 「今年一番のアイデア」「反則級の企画」

### C3. Do / Don't
**Do**
- 動画（16:9、15〜45秒に編集済み）を最優先で添付する
- 本文は日本語で実質100〜140字（重み換算で140字前後）に収め、改行で区切る
- 出典・特設サイトURLはセルフリプライ（本文投稿直後の自分への返信）に置く
- 数字・固有名詞を1行目に前出しする
- 締めに問いかけ or 断定的評価を置き、返信を誘発する
- 投稿直後15〜30分は反応できる時間帯を選ぶ（日本時間 平日7-9時/20-22時、週末14-17時）

**Don't**
- 本文中に外部リンクを貼らない（アルゴリズム上のペナルティが一次情報で確認済み、A3）
- ハッシュタグを大量に付けない（拡散効果はほぼ消失、A6）
- 釣りタイトルで炎上・通報を誘発しない（通報の負の重みは最大級、A4）
- 絵文字を装飾目的で多用しない（文字数消費が2倍、可読性も低下）
- 1文が長すぎる/改行なしの壁テキストにしない

### C4. メディア選定ルール
1. 動画素材がある → 16:9 or 9:16、15〜45秒に要点だけ切り出して添付（最優先）
2. 動画がない/長尺のみ → 象徴的な1シーンの静止画（16:9推奨、1200×675px以上）
3. Before/Afterがある施策 → 2枚組（左右 or 上下）で静止画比較
4. サイト/インタラクティブ体験 → 操作画面の短いスクリーン録画（GIFでも可、ただし動画の方が画質・尺の自由度が高い）

### C5. リンク配置ルール
- 本文（メイン投稿）には出典・特設サイトURLを含めない
- 投稿直後に自分でその投稿へ返信し、そこにURLを記載する（「詳細はこちら→」等の一言＋リンク）
- スレッド形式の場合は最終投稿にリンクをまとめる

### C6. 長さ目標
- 単発ポスト本文: 日本語で3〜5行、実質70〜140字（重み換算目安。URLは含めない前提）
- スレッド1投稿目: 単発ポストと同基準（単独で成立する強度が必須）
- スレッド2投稿目以降: 各100〜150字程度、1トピック1投稿

### C7. LLMプロンプトに組み込むチェックリスト
生成後、以下をすべて満たすか自己検証させる:
- [ ] 1行目だけで「何がすごいか」が伝わるか（固有名詞または数字を含むか）
- [ ] 本文に外部URLを含んでいないか
- [ ] ハッシュタグを3個以上使っていないか
- [ ] 絵文字は2個以内か
- [ ] 改行で3〜5ブロックに分かれているか（壁テキストになっていないか）
- [ ] 締めに問いかけ・断定評価など返信を誘発する一言があるか
- [ ] 添付予定メディアが動画（16:9 or 9:16、15〜45秒）か、なければ静止画1〜2枚を指定しているか
- [ ] 日本語の重み換算で140字前後に収まっているか（1文字=2カウントで計算）
- [ ] 出典URLはセルフリプライ用として別出力になっているか
