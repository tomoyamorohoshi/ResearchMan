# LINE「X投稿」タブ 設計 — 2026-09-27 合意（v2・旧「候補一覧プル型」案は破棄）

## 目的
@tomoyamorohoshi のXで事例紹介するため、LINEに「X投稿」タブを作り、RMの事例/技術ページURLを投げると「Xに最適化した投稿文」と「添付用の画像（動画は扱い下記）」が返ってくる。選出は人（URLを送る＝選出）。

## 根拠資料
- 投稿文の法則・X仕様/アルゴリズム: `docs/X_POST_RESEARCH.md`（生成プロンプトはここのセクションCを要約して組み込む）

## ユーザーフロー
1. リッチメニューの「X投稿」ボタン（またはテキスト `X投稿`）→ 「RMの事例/技術ページのURLを送ってください」を reply
2. ユーザーが URL を送る（`https://research-man.vercel.app/cases/{id}` / `/technology/{id}`。末尾スラッシュ・クエリ・`#`可、`www.`無し前提、プレビュー等別ホストは不可）
   - RM以外のURL・存在しないid → エラー文を reply し、同タブのまま再入力待ち
3. 生成（Claude Agent SDK＝既存 sdkRunner 経由・Sonnet・ローカルClaude Code認証。従量課金APIは使わない）
4. 結果を返す（まず reply を試み、トークン失効なら既存と同じく push にフォールバック。1回の送信に吹き出し最大5個をまとめ、push時も枠消費は1通）
   - 吹き出し①: 投稿文 案A（フック型）
   - 吹き出し②: 投稿文 案B（別のフック/構成）
   - 吹き出し③: セルフリプライ用テキスト（RMページURL＋一次ソースURL。本文にはリンクを入れない＝X_POST_RESEARCHのリンク減点対策）
   - 吹き出し④: 画像メッセージ（thumbnail。`https://research-man.vercel.app/thumbnails/{id}.jpg` / `/thumbnails/tech/{id}.jpg`。本番で200を確認できない場合は省略し注記）
   - 動画: 事例に YouTube videoId / 技術に video リンクがある場合、③に「動画: {URL}（公式動画。Xへは引用・リンクで紹介。ダウンロード転載はしない）」を追記。**動画ファイルの取得・再アップロードは著作権/規約上行わない**
5. 続けて別URLを送れば同タブで連続生成。`キャンセル` で終了（既存予約語）

## 投稿文の生成仕様（要点。詳細は X_POST_RESEARCH.md C）
- 事実紹介ベース。入力は cases.json/tech.json の該当エントリのみ（summary/overview/execution/evaluationImpact/award/client/year 等）。**エントリに無い事実・数字を足さない**（ハルシネーション禁止をプロンプトで明示）
- 1行目で結論＋固有名詞（＋データにあれば数字）を言い切る。改行で読みやすく。絵文字は0〜1。ハッシュタグなし。本文にURLなし
- 締めは問いかけ or 断定で返信を誘発（煽り・釣りは不可）
- 長さ: X加重文字数（CJK=2・その他=1・URL=23）で **280以下**をコードで検証。超過なら1回だけ再生成依頼、それでも超過ならエラー扱いで案を落とす（切り詰めで意味を壊さない）
- 出力はJSON（案A/案B）で受け、コード側で検証してから整形
